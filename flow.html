Dialogue generation pipeline

任务被逐步披露，Code 在隔离候选中工作，Judge 私下验收；公开产物只保留 User 与 Code 的最终消息。

1 · Task sourceissue、commit、PR 或连续任务
2 · Decompose拆成可逐步释放的信息片段
3 · User状态机选择合法动作，User 自己表达
4 · Code读取、修改并测试候选实现
5 · Judge在独立副本中判断 solved / unsolved / uncertain
6 · Continue失败则反馈，成功则接受或自然追问
7 · Export输出纯公开 dialogue

User

  • 只看已释放需求与公开对话
  • 没有仓库读取工具
  • 用状态机约束推进方式

Code

  • 只看公开 User 消息
  • 候选工作区可写
  • 看不到参考修复和未来任务

Judge

  • 查看完整当前任务
  • 候选和参考只读
  • 私有检查不会直接进入公开对话
循环规则： unsolved → 一条可观察反馈 → User → Code → Judge； solved → 接受 / 解释追问 / 运行验证； uncertain → 保留现场，不伪造通过。

公开输出

dialogue.json 与 dialogue.html 只含双方公开文本。工具事件、Judge 证据、参考材料、模型请求和 checkpoint 保留在本地忽略目录中。
